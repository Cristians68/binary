# Binary Academy

IT certification study app — flashcard lessons, timed quizzes, streaks and
badges — built in Flutter, shipping to iOS with a Firebase backend.

Version `1.0.0+49`. Primary target is iOS; Android, web, macOS and Windows
targets exist and build, but only iOS and web are exercised.

---

## Layout

```
lib/
  main.dart                 App bootstrap, Firebase init, theme wiring
  course_catalog.dart       Canonical course list + trademark-safe display names
  security_service.dart     Jailbreak/integrity checks (native only)
  firebase_options.dart     Generated by flutterfire; do not hand-edit
  screens/                  Every screen plus the service layer it talks to
    quiz_logic.dart         Pure quiz scoring + answer shuffling (tested)
    review_logic.dart       Pure spaced-repetition scheduling (tested)
functions/
  index.js                  Cloud Functions entry point
  entitlements.js           RevenueCat webhook + server-authoritative access
  account.js                Atomic account deletion
admin/seed/                 One-shot Firestore content seed scripts
docs/SECURITY.md            Security model and the mandatory deploy runbook
docs/CONTENT.md             Content accuracy pass, seeding rules, validator
docs/REVIEW.md              Spaced-repetition review feature
firestore.rules             Firestore authorization rules
test/                       Flutter tests
```

`lib/screens/` holds both UI and services (`auth_service.dart`,
`progress_service.dart`, `streak_service.dart`, `subscription_service.dart`,
`offline_service.dart`, `notification_service.dart`). The name is historical —
services are not screens, they just live alongside them.

## Two rules that are easy to get wrong

**1. Entitlements are server-authoritative.** Course access is decided by a
document the client cannot write, populated by the RevenueCat webhook in
`functions/entitlements.js`. Never reintroduce a client-side read of
`users/{uid}.subscriptionPlan` as an access check — that was the exact
vulnerability `docs/SECURITY.md` §1 describes, and it made the whole paid
catalogue free.

**2. Deploy order is not optional.** `docs/SECURITY.md` §5 gives the required
order. Deploying Firestore rules before the functions that satisfy them locks
out live users. Read it before any `firebase deploy`.

**3. Quiz answer order is load-bearing.** The authored content puts the correct
answer at index 1 about 92% of the time. `shuffleQuizQuestions` in
`lib/screens/quiz_logic.dart` is what stops "always tap the second option" from
passing every quiz in the app. Do not remove or simplify it away — see
`docs/CONTENT.md` §3.

## Course naming

Course titles must come from `lib/course_catalog.dart`, never string literals.
Certification marks ("ITIL", "CSM", "Network+") are owned by other
organizations; using one as a product name implies an affiliation we do not
have and breaches App Store Review Guideline 5.2.1. `displayTitle` returns the
ownable product name; `preparesFor` returns the factual, nominative reference.

The internal `id` and `tag` values are deliberately *not* trademark-scrubbed —
they are matched against live Firestore documents and against switch statements
in the lesson and quiz screens. Renaming one orphans real user progress.

## Running it

The Flutter SDK is not assumed to be on `PATH`.

```bash
flutter pub get
flutter run -d chrome              # or: -d web-server --web-port 8080
```

### Developing on Windows

Xcode's iOS Simulator is macOS-only, so on Windows the web target is the
substitute:

```bash
flutter run -d web-server --web-port 8080 --web-hostname 127.0.0.1
```

The web build is a layout and logic proxy, not an iOS runtime. These do **not**
work there and are `kIsWeb`-guarded — keep any new native call guarded the same
way or the web build breaks at startup:

- `flutter_local_notifications` — local notification scheduling
- `firebase_messaging` — push
- `sign_in_with_apple` — native Apple sign-in flow
- `flutter_jailbreak_detection` — device integrity
- `purchases_flutter` — real StoreKit purchases

Real iOS verification needs a Mac: a cloud Mac, the configured Codemagic
pipeline (`codemagic.yaml`), or a streamed simulator.

### Tests

```bash
flutter test
```

## App Store notes

`ios/Runner/PrivacyInfo.xcprivacy` is the app-level privacy manifest, required
by App Store Connect since 2024-05-01. It is wired into the Runner target's
Copy Bundle Resources phase — a manifest that is only present on disk is not
shipped and the upload is still rejected.

If you add a dependency or start collecting a new field, update **both** that
file and the App Store Connect "App Privacy" questionnaire. Review cross-checks
the two. Each CocoaPod ships its own manifest; do not restate pod declarations
in the app-level file.

## Content seeding

`admin/seed/` writes course content straight to production Firestore. The
scripts are one-shot and not idempotent in the way you would hope. Read the
header comment in each before running it, and see `docs/SECURITY.md` for
credential handling.
